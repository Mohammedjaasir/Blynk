## W-B1 API (bundle offers backend; migration 062 adds order_items.bundle_* columns)
Until 062 is run: GET /store `bundle_offers` is `[]`, no offer is applied, `GET /admin/settings/bundle-offers` answers with `ready:false` (rules can still be edited and saved), orders carry `bundle_savings: 0`, `gift_items: []`.

Money model: a free unit is a SEPARATE order line (same product, unit price 0, quantity = free units), so `subtotal_amount` = what is charged for items; coupon / points / wallet / delivery-free threshold all work on that subtotal. A gift is an extra line, price 0, quantity gift_qty.

### Staff settings: GET | PUT /admin/settings/bundle-offers (ADMIN, OPERATIONS; audited BUNDLE_OFFERS_UPDATED)
PUT body replaces the whole list: `{ offers: Offer[] }` (max 10, order = priority). An offer without `id` gets one from the server.
```
Offer (BUY_X_GET_Y): { id?, type:'BUY_X_GET_Y', title (2-40 chars), is_active (default true), starts_at|null, ends_at|null (ISO with offset),
  buy_qty 1-10, get_qty 1-10, product_ids: uuid[] (1-20) | null, category_id: uuid | null }   // exactly ONE of product_ids / category_id
Offer (SPEND_GET_GIFT): { id?, type:'SPEND_GET_GIFT', title, is_active, starts_at, ends_at, min_subtotal (LKR, >0), gift_product_id: uuid, gift_qty 1-10 (default 1) }
```
Fields not used by the type are returned as null. Response (GET and PUT): `{ ready: boolean, offers: OfferView[], updated_at }` where
`OfferView = Offer & { id, status:'LIVE'|'SCHEDULED'|'ENDED'|'OFF', product_names:[{id,name}], category_name|null, gift_product_name|null }`.
A category matches products of that category and of its sub-categories (the product primary category). Errors: 400 VALIDATION_ERROR (field paths under `offers.N.*`), 400 PRODUCT_NOT_FOUND, 400 CATEGORY_NOT_FOUND.

### Public: GET /store `bundle_offers` (LIVE offers only, rule order, [] before 062)
```
{ id, type, title, ends_at|null, buy_qty|null, get_qty|null, product_ids: string[]|null, category: {id, slug}|null,
  min_subtotal|null, gift_product_id|null, gift_product_name|null, gift_qty|null }
```
BUY_X_GET_Y wording: "Buy {buy_qty} get {get_qty} free" (the cheapest {get_qty} of every {buy_qty+get_qty} matching units are free).

### Customer quote: POST /orders/bundle-quote (auth, shoppers)  body: `{ items:[{product_id, variant_id?, quantity}], combos? }` (same shape as POST /orders)
`data`:
```
{ ready: boolean,
  subtotal_before_bundles, bundle_savings (free units + gifts, LKR), subtotal (charged for items, after bundles),
  bundle_applied: [{ offer_id, title, type, savings_lkr, free_units?: number, gift?: { product_id, name, quantity, value_lkr } }],
  gift_items: [{ product_id, name, quantity, value_lkr, offer_id }],
  bundle_progress: null | { offer_id, title, type,
      remaining_units?: number,   // BUY_X_GET_Y: add this many more matching units to unlock the next free ones
      remaining_lkr?: number,     // SPEND_GET_GIFT: spend this much more to unlock the gift (only when the gift is in stock)
      get_qty?, buy_qty?, product_ids?, category_id?, gift_product_id?, gift_product_name?, gift_qty? },
  lines: [{ product_id, variant_id|null, quantity, paid_quantity, free_quantity, unit_price }] }   // one per requested line, in request order
```
The same fields `subtotal_before_bundles, bundle_savings, bundle_applied, gift_items, bundle_progress` are also added to POST /orders/validate-coupon `data.coupon` (its `subtotal` is already after bundles; a coupon is worked out on that subtotal). Free units come out of the units the customer ordered (3 ordered with "buy 2 get 1" = 2 paid + 1 free, still 3 units); only a gift is an extra item. Quotes are advisory: a gift that sells out between the quote and the order is simply left off the order (never an error).
PUT note: the body of GET can be sent back as it is (the read-only fields `status`, `product_names`, `category_name`, `gift_product_name` and the null fields of the other type are ignored).

### Orders (customer POST /orders, GET /orders, GET /orders/:id, repeat baskets; staff GET /admin/orders/:id)
Added on every order: `bundle_savings: number`, `bundle_applied: [...same shape as the quote]`, `gift_items: [{ item_id, product_id, name, quantity, value_lkr, offer_id }]`.
Every item in `items[]` also has: `is_bundle_free: boolean` (true for a free unit line OR a gift), `bundle_kind: 'FREE_UNITS'|'GIFT'|null`, `bundle_offer_id`, `bundle_title`, `bundle_value` (LKR it would have cost; null when not a bundle line). Show these lines as "Free" / "Gift".
Removal by staff (RESOLVE_ITEM) re-checks BUY_X_GET_Y: free units never exceed what the remaining paid units earn; gifts stay.
