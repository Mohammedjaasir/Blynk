# Delivery fee formula, small-order fee, delivery radius (contract)

Owner's brother's request (2026-10-25). Every value is editable from Admin -> Settings (and Ops), never
hard-coded. The backend (done by the lead, in `backend/api`) is described here so the UI agents can build
against it; do not edit `backend/api`.

## 1. Delivery fee "base + per km" (new fee mode `BASE_PER_KM`)

`delivery_fee` setting gains a third mode next to FLAT and DISTANCE_TIERS:

    fee = base_lkr                                  while distance <= base_km
    fee = base_lkr + per_km_lkr * ceil(distance - base_km)   beyond it (every STARTED km counts), then the
                                                    optional cap max_fee_lkr (existing)
    defaults: base_lkr 120, base_km 2, per_km_lkr 40.
    1.5 -> 120 | 2.0 -> 120 | 2.1 -> 160 | 3.0 -> 160 | 3.4 -> 200 | 4.8 -> 240 | 5.6 -> 280

* `GET /admin/settings/delivery-fee` (ADMIN, OPERATIONS) returns
  `{ fee_lkr, fee_mode: 'FLAT'|'DISTANCE_TIERS'|'BASE_PER_KM', tiers, max_fee_lkr, base_lkr, base_km, per_km_lkr, updated_at }`
  (`base_lkr/base_km/per_km_lkr` are always present, defaults above when never saved).
* `PATCH /admin/settings/delivery-fee` takes the same fields, all optional (only what is sent changes):
  `fee_mode`, `fee_lkr` (0-1000, flat), `tiers`, `max_fee_lkr`, plus `base_lkr` (0-1000, 2 decimals),
  `base_km` (0.5-20, at most 1 decimal), `per_km_lkr` (0-1000, 2 decimals). 400 with the usual
  `VALIDATION_ERROR` details on bad numbers.
* Public `GET /store` (customer app): for `BASE_PER_KM` the public `delivery_fee_mode` is `'DISTANCE_TIERS'`
  (older apps keep working), `delivery_fee_by_distance: true`, `delivery_fee_lkr: null`,
  `delivery_fee_from_lkr: base_lkr`, and a NEW `delivery_fee_formula: { base_lkr, base_km, per_km_lkr, max_fee_lkr } | null`
  (null for FLAT and DISTANCE_TIERS) so the cart can say "LKR 120 up to 2 km, then LKR 40 for each extra km".
* `GET /orders/checkout-info` keeps `delivery_fee_lkr` (charged), `standard_delivery_fee_lkr`,
  `delivery_distance_km`, `delivery_distance_estimated`, `delivery_fee_mode` ('DISTANCE_TIERS' for this mode).

## 2. Small-order fee (switch, OFF by default)

* Stored with the other checkout switches: `GET/PATCH /admin/settings/checkout` gains
  `small_order_fee: { enabled: boolean, min_subtotal_lkr: number, fee_lkr: number }`
  (defaults `{ enabled: false, min_subtotal_lkr: 1000, fee_lkr: 50 }`; min 1..100000, fee 0.01..1000, 2 decimals).
  The GET also returns `small_order_fee_ready: boolean` (false until migration 063 has been run by hand in
  Coolify). PATCHing `enabled: true` while not ready answers 409 `SMALL_ORDER_FEE_NOT_READY` with message
  "Run migration 063 in Coolify before switching the small-order fee on." - show that message as the error.
* The fee applies when the item total (order subtotal after item/category offers and bundle/combo prices,
  before coupons/points) is UNDER `min_subtotal_lkr`. Free delivery does NOT waive it. It is not part of the
  delivery fee, so it never touches rider pay (the rider still earns their % of the STANDARD delivery fee).
* `GET /store` gets `small_order_fee: { enabled, min_subtotal_lkr, fee_lkr }` (`enabled` is false while not ready).
* `GET /orders/checkout-info?subtotal=` gets `small_order_fee: { enabled, min_subtotal_lkr, fee_lkr, applies: boolean|null, charged_lkr: number, remaining_lkr: number|null }`
  (`applies` null without ?subtotal=; `charged_lkr` = the fee when it applies else 0; `remaining_lkr` = LKR still
  to add to avoid it, 0 once reached, null when off / no subtotal).
* `POST /orders/validate-coupon` response gets `small_order_fee_lkr` (number) and its `total` includes it.
* Every order object (customer order, admin/ops/rider order views) gets `small_order_fee: number` (0 when none);
  `total_amount` already includes it.
* Customer cart copy (exact English): separate line **"Small-order fee"**, and while the fee applies and
  `remaining_lkr > 0` the message **"Add LKR {X} more to avoid the small-order fee."** (X formatted like the
  other LKR amounts in the cart, no decimals when whole).

## 3. Delivery radius

* `GET /admin/settings/delivery-radius` (ADMIN, OPERATIONS) -> `{ radius_km: number, store_name: string }`
* `PATCH /admin/settings/delivery-radius` `{ radius_km }` (0.5-50, at most 2 decimals) -> same shape.
  It changes the active store's service radius: new addresses/orders beyond it are refused
  (DELIVERY_OUTSIDE_RADIUS), the customer app's delivery-area map follows it. Currently 4 km; the owner will
  set 6 km next week.

## 4. Free delivery above an amount

Already exists (`basket_free_delivery` in `/admin/settings/checkout`, OFF by default; at or above the amount).
The rider is still paid their normal % (default 80) of the STANDARD fee even when the customer pays 0.
No change needed except the Admin/Ops screens should word it clearly (see below).
